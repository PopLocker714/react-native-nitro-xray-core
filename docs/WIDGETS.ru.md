# Виджеты на домашнем экране

Всё написанное ниже добыто тем, что виджет был выпущен на обеих платформах и
сломался на живых устройствах. Прочитайте до того, как писать свой, а не после.

## Правило, из которого следует всё остальное

**Виджет работает тогда, когда ваш JS не работает.** Пользователь жмёт его при
смахнутом приложении: нет ни рантайма React Native, ни стора, ни хуков — ничего
из написанного на JS не живо. Любая способность, нужная виджету, обязана
существовать нативно.

Из одного этого ограничения следует всё дальнейшее.

## Быстрый доступ: воспроизведение, а не построение

Виджет не может построить конфиг: для этого нужна подписка, список серверов и
ваш JS. Поэтому он воспроизводит последний конфиг, который сработал.

```ts
// Согласие даётся один раз, например при старте приложения.
// До этого ничего не сохраняется.
await XrayClient.setQuickConnectEnabled(true)

// Возможно ли подключение одним тапом прямо сейчас.
const ready = await XrayClient.isQuickConnectReady()
```

Android сохраняет полезную нагрузку только после **успешного** старта, поэтому
виджет не может воспроизвести конфиг, заведомо не работающий.

### У обхода две половины

Если вы предлагаете обход через olcrtc, помните: его конфиг xray дозванивается
на `127.0.0.1:<socks>` — порт, существующий, только пока работает olcrtc.
Воспроизведение одного этого конфига поднимает туннель в пустоту: подключено,
тихо, ошибок нигде.

Библиотека хранит клиентский конфиг olcrtc **рядом** с конфигом xray и при
быстром старте поднимает обход **перед** движком. Это работает само, помнить
нужно другое: хотя бы один раз подключиться через обход из приложения, иначе
воспроизводить будет нечего.

## Android

### Подключение

```kotlin
// Старт из сохранённой нагрузки. Только startForegroundService: сервис сам
// входит в foreground, а тап по виджету — принятое системой исключение из
// запрета фоновых стартов.
ContextCompat.startForegroundService(context, XrayVpnService.quickConnectIntent(context))

// Остановка. Обычный startService: ветка остановки намеренно не входит в
// foreground.
context.startService(XrayVpnService.stopIntent(context))
```

Сначала проверьте `QuickConnectStore.isReady(context)`, а также
`VpnService.prepare(context)`: системный диалог согласия требует Activity, и из
ресивера остаётся только открыть приложение, а не отказать молча.

### Как держать подпись честной

Сервис рассылает `<applicationId>.XRAY_STATE_CHANGED` при каждой смене
состояния. Подпишитесь в манифесте:

```xml
<receiver android:name=".widget.VpnWidgetProvider" android:exported="false">
    <intent-filter>
        <action android:name="android.appwidget.action.APPWIDGET_UPDATE"/>
        <action android:name="${applicationId}.XRAY_STATE_CHANGED"/>
    </intent-filter>
</receiver>
```

Так сделано потому, что слушатель состояния в библиотеке **один** и уже занят
мостом в JS. Второй подписчик молча убил бы обновления во всём приложении.
Широковещание — это способ узнать состояние для точки входа без JS, а ресивер,
объявленный в манифесте, переживает мёртвый процесс.

### Переход заканчивается по ДВИЖКУ, а не по туннелю

TUN поднимается примерно за 200 мс. Обход после этого договаривается с
ретранслятором ещё секунду-другую. Если считать «подключено» по туннелю, в этом
окне `isRunning == true`, а `isEngineRunning == false` — а это по определению
библиотеки блэкхол под kill switch, и виджет скажет «трафик заблокирован» на
совершенно здоровом подключении.

```kotlin
val settled = if (connecting) XrayVpnService.isEngineRunning else !XrayVpnService.isRunning
```

### Вибрации нужен HARDWARE_FEEDBACK

Виджет обрабатывает тап в фоновом ресивере, а с Android 12 система глушит
фоновые вибрации с назначением `TOUCH` (`Ignoring incoming vibration as process
is background`). Используйте `VibrationAttributes.USAGE_HARDWARE_FEEDBACK` — оно
описывает отклик на физическое действие и из фона разрешено.

## iOS

### WidgetKit перерисовывает виджет один раз за тап

В момент, когда `perform()` **возвращается**. Только эта перерисовка не
попадает под бюджет обновлений. Всё остальное задушено:

| Механизм | Что на самом деле |
|---|---|
| `reloadAllTimelines()` из приложения на переднем плане | работает: приложение на переднем плане — документированное исключение |
| `reloadAllTimelines()` из Network Extension при мёртвом приложении | **не доходит**: в списке исключений его нет |
| `.after(n)` при n меньше ~5 минут | не выполняется; Apple просит разносить записи примерно на 5 минут |
| `.never` | означает «пока приложение не попросит», то есть никогда при мёртвом приложении |

Отсюда: **не возвращайтесь из `perform()`, пока состояние не станет пригодным
для показа.** Вернётесь раньше — гарантированная перерисовка нарисует
переходное состояние, и оно залипнет.

`.never` здесь не использовать никогда. Устоявшимся состояниям дайте пол в
`.after(15 минут)`, чтобы упавший сам по себе туннель со временем вылечился.

### NEVPNStatus недостаточно

Он становится `connected` за доли секунды, а обходу нужны секунды — в плохой
день до тридцати. Зелёное «Подключено» над туннелем, который ещё не может везти
трафик, хуже честного «поднимаю обход».

Фаза обхода обязана ехать своим каналом. Пишите её из Network Extension в App
Group **файлом**: у `UserDefaults` есть межпроцессный кеш, из-за которого
доставка NE→app ненадёжна, а у `Data(contentsOf:)` такого кеша нет.

### Подтверждение нажатия

Публичного API тактильного отклика из расширения виджета нет:
`UIImpactFeedbackGenerator` требует `UIWindowScene` и без него молча ничего не
делает. `AudioServicesPlaySystemSound(kSystemSoundID_Vibrate)` работает, но это
полноценная вибрация без возможности смягчить — мы попробовали и убрали, для
переключателя слишком грубо.

Подтверждайте нажатие **подписью**: запишите намерение пользователя в общее
хранилище, отрисуйте его сразу и снимите до возврата, чтобы гарантированная
перерисовка нарисовала правду.

### Фильтруйте профиль

`loadAllFromPreferences()` возвращает все VPN-профили на устройстве.
Сопоставляйте по `providerBundleIdentifier`, ровно как это делает библиотека
внутри, иначе рано или поздно будете управлять чужим VPN.

### Возвращайте то, что забрали

Если снимаете правило on-demand, чтобы явная остановка сработала, спрячьте
пометку в `providerConfiguration` и восстановите при следующем старте. Иначе
один тап по виджету навсегда выключит пользователю always-on.

## Уведомление (Android)

`setNotificationConfig({ text })` принимает плейсхолдер `{connection}`, вместо
которого подставляется живое подключение: явный `label`, иначе тег сервера.

```ts
XrayClient.setNotificationConfig({ text: 'Подключено · {connection}' })

// У режима только-обход тега сервера нет, поэтому имя задаёте сами:
await XrayClient.connectOlcrtcOnly({ label: 'Обход блокировок' })
```

Без плейсхолдера текст используется как есть, так что существующие интеграции
это не затрагивает.
